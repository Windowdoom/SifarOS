# SifarOS 2.0 independent security review

This file tracks the independent review received for `sifar/2.0-dev` and the engineering response.

## Rule for 2.0 development

Browser/network feature work is gated on security prerequisites. Findings are fixed and boot-tested before the browser is allowed to consume untrusted network content.

## Findings

| Finding | Status | Response |
|---|---|---|
| C1: no hardware W^X/NX | Open, release blocker | Move to PAE + NX before untrusted browser rendering. ELF W+X rejection remains defense-in-depth only. |
| C2: PMM could return frames outside direct map | Fixed | PMM now manages only identity-mapped low physical memory until a high-memory mapping layer exists; E820 arithmetic stays 64-bit. |
| C3: SifarFS trusted superblock sizes/regions | Fixed | Mount validates all metadata ranges/capacities against the actual device before allocation/read. |
| H1: arbitrary `SYS_KILL` | Fixed | Only direct parents, kernel, or a process holding `PROC_CAP_PROCESS_CONTROL` can kill another process. |
| H2: cross-process activate/minimize | Fixed at syscall boundary | Window control is owner-scoped unless the caller holds `PROC_CAP_WINDOW_CONTROL`; the desktop receives that capability explicitly. |
| H3: unvalidated SifarFS data block pointers | Fixed | Direct/indirect pointers and device LBAs are range checked and metadata blocks are never data allocations. |
| M1: `kcalloc` multiplication overflow | Fixed | Overflow is rejected before allocation. |
| M2: negative `argc` landmine | Fixed | Stack construction and spawn entry validate signed argc and bounded argument storage. |
| M3: ATA polling | Open | Convert spin-count waits to timer-based timeouts with cooperative yields. |
| M4: PCI command omitted memory-space enable | Fixed | PCI bus-master enable now sets I/O, memory and bus-master command bits. |
| M5: Sentinel passive only | Open, release blocker | Add enforceable policy actions and capability revocation before hostile content. |
| M6: SMEP/SMAP | Planned | Enable where supported after paging/PAE transition is stabilized. |

## Capability foundation

SifarOS 2.0 now has kernel-granted, non-inherited process capabilities. No userspace syscall can grant capabilities. Initial capability bits cover global window control, system power control, process control/inspection, and networking. The desktop is granted only window and system-control capabilities at boot.

## Next security gates

1. Boot/CI verification of this hardening batch.
2. Add malformed SifarFS regression images and >1 GiB memory boot coverage.
3. Implement PAE + NX and enforce executable vs writable mappings at page-table level.
4. Add guard pages for kernel/user stacks where practical.
5. Add Sentinel enforcement policy and capability revocation.
6. Resume NIC/TCP/browser implementation only after the above browser-facing prerequisites pass.
